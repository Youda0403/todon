# 답글 참조 상자와 불러오기 개선

비교 기준: main `03f269bf29ca5ebd714bb01e75c46b245739c1a8`.

## 답글 상자를 접고 펼칠 때

삼성 브라우저 실기기 영상에서 키보드를 켠 채 상자를 접거나 펼치면 작성 중인
입력칸으로 화면이 내려가는 현상이 계속됐다. 앞선 한 프레임 위치 복원만으로는
해결되지 않았다는 사용자 보고가 있었다.

기존 코드에 박스 클릭 100ms 뒤 **내용이 변하지 않은** 입력 이벤트를 보내면,
펼칠 때 스크롤이 0 → 483, 접을 때 0 → 302로 이동하는 경로를 Chromium에서 재현했다.
실제 삼성 키보드가 이 이벤트를 보냈다는 증거는 아직 없다.

- 내용이 같은 입력 이벤트에는 재배치·저장·커서 스크롤을 하지 않는다.
- 폼 상태 갱신과 커서 따라가기를 분리한다. 실제 입력과 이모지 삽입 때만 커서를 따라간다.
- 상자를 누른 순간의 위치를 기억해 브라우저의 지연 자동 스크롤도 차단한다.
  다음 터치, 터치 스크롤, 휠, 키 입력 또는 실제 글 변경에서 즉시 해제한다.
  반복 타이머나 프레임 루프는 사용하지 않는다.
- 키보드 유지를 위한 포커스 보존과 프로필·링크·미디어 동작을 유지한다.

## 새로고침과 게시 뒤 대기

기존 타래 화면은 새로고침마다 글을 먼저 지운 뒤 툿·대화 전체 요청을 함께 기다렸다.
게시 응답에 새 툿이 들어 있어도 응답을 사용하지 않고 다시 타래를 요청했다.
이 구조는 이전 Claude 코드에도 있던 것으로, Codex 수정 이후 느려졌다는 원인으로
확정한 것은 아니다. 실제 서버 응답 시간은 사용자 기기의 기록이 필요하다.

- 타래를 다시 받는 동안 기존 내용을 유지하며, 중복 새로고침 요청을 합친다.
- 같은 계정에서 게시에 성공하면 반환된 툿을 타래 또는 해당 홈 목록에 바로 넣는다.
  이 경우 게시 뒤 목록을 받기 위한 추가 요청은 하지 않는다.
- 이전에 시작한 새로고침 응답이 나중에 와도 막 올린 답글을 보존한다.
- 홈 목록의 조회 기준은 서버 응답으로만 갱신해, 내 게시물 사이에 도착한 다른 글을 건너뛰지 않는다.
- 수정·삭제 결과도 화면의 임시 데이터에 반영한다.
- 다른 계정으로 게시했거나 화면이 아직 준비되지 않은 경우에는 기존 새로고침 경로를 사용한다.

새 글의 서버 등록 자체에 걸리는 시간은 이 변경으로 단축됐다고 보장할 수 없다.

## 기기에서 확인하는 기록

설정 → **문제 확인용 기록 복사**.

최근 80개만 메모리에 보관하며 앱을 새로 열면 사라진다. API 종류·메서드·응답 상태·
소요 시간과 상자 토글·중복 입력 이벤트·스크롤 수치만 기록한다.
본문, 키보드 입력 내용, URL, 계정, 토큰은 기록하지 않는다.
복사는 사용자가 버튼을 누를 때만 실행하며 자동 전송하지 않는다.

키보드를 켜고 문제 동작을 재현하거나 느린 새로고침·게시를 한 직후, 앱을 다시 열지 말고
기록을 복사하면 실제 기기의 추가 원인 구분에 사용할 수 있다.

## 검증

```sh
node --test tests/*.test.cjs
```

기존 알림 복구, 타래 요청 공유·내용 유지·게시/새로고침 경합·수정/삭제 반영,
요청 기록의 민감 정보 제외와 크기 제한을 검사한다.

별도 Chromium 모바일 검사에서 접기·펼치기와 지연 IME 이벤트, 브라우저의 지연 자동
스크롤 차단, 신뢰된 터치 스크롤의 해제, 정상 입력 시 커서 이동, 실제 게시 버튼과
타래·홈 즉시 표시, 게시 실패 시 초안 보존, 조회 기준과 게시 순서, 기록 복사를 확인했다.
삼성 브라우저의 실제 키보드·네트워크 환경은 직접 검증하지 못했다.
