# 답글 우선 표시와 같은 툿 재진입 복원

비교 기준: main `0210322309c6adb9e282041a82e367c499e020e2`.

## 사용자 기록에서 확인된 구간

진단 버전 2026-10-18.6, 2026-10-18 23:39~23:41 KST.

| 타래 진입 | 본문 준비 | 최신 본문 조회 | 답글·이전 글 조회 | 전체 타래 표시 |
| --- | ---: | ---: | ---: | ---: |

| trace 256 | 보관 본문 5ms | 4,895ms | 267ms | 본문 포함 6개 카드, 진입 약 4,910ms 뒤 |

두 번째 진입에서는 답글 목록이 먼저 도착했지만 약 4.6초 동안 추가로 기다렸다.
이전 수정은 본문이 먼저 오면 표시했으나, 코드의 `await statusRequest` 때문에
답글이 먼저 왔을 때는 보관 본문과 함께 표시할 수 없었다. 마지막 DOM 구성은 8ms였다.

같은 기록에 알림 조회 11,004ms, 쪽지 조회 32,095ms의 헤더 미수신·시간 초과가 있다.
이는 툿 타래 조회의 시간 초과 기록이 아니다. 사용자가 보고한 다른 툿 진입의
“서버 응답 없음” 원인을 이 복사본만으로 확정할 수 없다. 재시도 직후 조회들이
다시 짧아진 것은 관측됐지만 서버 처리·통신·브라우저 상태 중 어느 원인인지 분리되지 않는다.

## 수정

- 본문과 타래 응답을 서로 기다리지 않고 각각 반영한다. 이미 받은 본문이 있으면
  답글 목록이 도착하는 즉시 함께 표시한다. 본문이 없으면 먼저 온 타래를 보관해
  본문 도착 시 표시한다. 본문 우선 도착도 계속 지원한다.
- 타래가 먼저 완성되면 직접 답글 개수를 표시하고, 아직 남은 작업을
  `본문의 최신 내용을 확인하는 중이에요`로 안내한다.
- 같은 툿을 다시 누를 때 기존 화면을 버리기 전에 본문·이전 글·답글·전송 직후의
  답글 보호 기록을 넘긴다. 새 화면에서 바로 복원하고 두 API를 다시 조회한다.
  원래의 최대 15개 화면 메모리 캐시를 활용하며 영구 저장이나 별도 무제한 캐시는 추가하지 않는다.
- 새 진입은 누른 툿에 초점을 맞추고, 뒤로가기는 기존 화면 스크롤을 복원한다.
  보관 타래에 긴 이전 글이 있어도 시작 글로 이동하지 않는다.
- 요청 실패가 다른 쪽의 성공 표시를 막지 않는다. 시간 초과 시 받은 본문·답글과
  오류 안내를 유지한다. `다시 시도`는 아직 남은 이전 조회를 취소하고 즉시 새 조회를 시작한다.
- 삭제·열람 불가·401·403 응답은 먼저 표시한 타래까지 걷어내고 안내한다.
  현재 계정·서버가 다르거나 삭제를 이미 확인한 툿은 재진입 복원에서 제외한다.
  숨긴 답글과 그 로컬 보호 기록도 넘기지 않는다.
- 답글 도착 후 본문 재확인이 남은 상태에서 이탈해도 미완료 검증 상태를 별도로 기억해,
  돌아왔을 때 다시 확인한다. 취소된 이전 응답이 새 화면을 덮지 않는다.
- 답글 목록에 로컬 답글을 합치는 처리는 응답당 한 번만 한다. 본문이 뒤늦게 도착해도
  방금 쓴 답글을 서버가 이미 확인했다고 오인해 보호 기록을 지우지 않는다.

## 진단과 검증

버전 2026-10-18.7. 답글 목록 준비의 `thread-replies`, 실패 단계의 `thread-error`,
타래 복원 여부의 `contextSnapshot`, 각 조회가 남아 있는지의 `statusPending`·`contextPending`을
추가한다. API 기록에는 요청 시작·완료 시 화면 숨김 여부를 추가한다. 중간에 얼마 동안
숨겨져 있었는지는 알 수 없으므로 이 값만으로 통신 실패 원인을 단정하지 않는다.
본문·주소·계정·토큰은 진단에 넣지 않는다. 준비 시간은 DOM 기준이며 실제 픽셀 표시 시간은 아니다.

`node --test tests/*.test.cjs`: 115개 통과. 타래 검사 30개는 기존 직접 답글 개수와
작성·수정·삭제, 양쪽 도착 순서, 시간 초과 후 유지·재시도, 늦은 삭제·권한 오류,
이탈 후 미완료 본문 확인, 재진입 복원, 계정 구분과 알려진 삭제 제외,
답글 보호 기록 유지, 잘못된 응답 안내, 다른 조회 중 즉시 재시도를 검사한다.

별도 411×922 모바일 Chromium 15개 시나리오에서 실제 API 경로를 가로채 응답 순서를 제어했다.
본문·답글 두 도착 순서, 본문 보관이 없는 경우, API 시간 초과와 재시도, 늦은 404·401·403,
라우터 재진입 복원과 최신화, 긴 이전 글의 초점, 답글 작성 보존, 이탈 취소와 늦은 응답,
삭제 복원 방지, 다른 조회 중 즉시 재시도, 진단 정보 범위를 확인했다.
테스트에서만 API 제한 시간을 줄여 실제 시간 초과 처리를 검증했다. 제품의 GET 제한은 10초다.
답글 우선 화면을 한글 글꼴로 렌더링해 확인했다.

사용자 서버와 삼성 브라우저 실기기에서의 새 응답 시간은 아직 측정하지 못했다.
서버·연결 자체의 지연을 해결했다고 주장하는 변경이 아니라,
먼저 받은 답글과 전에 읽은 타래를 불필요하게 가리는 대기를 제거하는 변경이다.
