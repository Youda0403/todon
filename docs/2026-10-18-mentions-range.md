# 멘션 관리의 최근 3일 자동 조회

비교 기준: main `a928ad1c3f17cc66aefc2c874e767906b7ad22c6`.

## 원인

기존 멘션 탭은 처음 40개를 읽었다. 이후에는 목록 끝이 화면에 가까워지거나
“더 오래된 멘션 불러오기”를 눌러야 다음 페이지를 조회했다.
특히 오래된 순에서는 스크롤에 따른 자동 조회도 꺼져 있었다.
하루 제한은 없었지만 멘션이 많으면 처음 40개가 하루 안에 몰려 있어,
2~3일 전의 안 답한 툿은 추가 동작 없이는 보이지 않았다.

## 변경

- 처음 진입 및 새로고침 때 최근 72시간을 모두 포함하는 페이지까지 자동으로 이어 읽는다.
  서버 기록이 먼저 끝나면 거기서 멈춘다. 72시간과 정확히 같은 시각의 항목도 포함한다.
- 정렬 순서, “안 답한 것만” 필터, 스크롤 위치에 관계없이 같은 범위를 읽는다.
- 알림은 한 번에 최대 80개를 요청한다. 서버가 더 적게 반환해도 계속 조회한다.
  받은 페이지의 답장 확인이 끝나면 그 페이지부터 표시한다.
- 쪽지·삭제·숨김 때문에 보이는 카드가 없는 페이지도 수신 시각을 기준으로 이어 읽는다.
- Link 헤더가 없을 때는 max_id로 다음 페이지를 조회한다.
  빈 응답이면 종료하고 같은 페이지가 반복되면 안내와 재시도로 멈춘다.
- 내 글 조회의 10페이지 제한을 없애, 글이 많은 계정에서도 해당 시점까지 답장 기록을 확인한다.
  이 조회도 빈 응답 종료, 중복 페이지 중단, max_id 대체 조회를 적용한다.
- 동시 진입·새로고침 요청은 같은 작업을 공유한다. 통신 오류는 받은 페이지를 유지하고
  실패한 페이지와 답장 기록의 이어지는 위치에서 다시 시도한다. 오류 직후 자동 반복하지 않는다.
- 추가 페이지를 표시할 때 읽던 카드를 같은 화면 위치에 둔다. 다른 화면으로 이동한 뒤
  완료되는 조회는 현재 화면을 스크롤하지 않는다.
- 자동 조회보다 오래된 멘션은 기존 더 불러오기와 스크롤 조회로 계속 볼 수 있다.

서버에서 이미 지워진 알림을 복원하는 변경은 아니다. 날짜 경계가 페이지 중간에 있으면
그 페이지에 포함된 더 오래된 멘션도 함께 표시한다.

## 검증

`node --test tests/*.test.cjs`: 75개 통과.

새 검사 12개는 72시간 범위, 정확한 경계, 필터로 비는 페이지, Link 헤더 없는 서버,
작거나 빈 기록, 페이지별 표시와 중복 새로고침, 오류 후 이어받기, 반복 페이지 중단,
400개를 넘는 내 글 뒤의 답장 기록, 답장 조회 실패와 재시도, 수동 과거 조회를 확인한다.

별도 모바일 Chromium 14개 시나리오에서 최신·오래된 순과 미답 필터,
2~3일 전 카드 표시, 답장/수동 제외 항목 처리, 답장 직후 제외, 지연 중 표시,
읽던 위치 보존, 오류 후 재시도, 40개 제한·Link 헤더 없는 서버, 쪽지·null 툿만 있는 페이지,
반복 페이지 안내, 빈 기록, 다른 화면의 스크롤 유지, 수동 과거 조회와 새로고침을 확인했다.
실제 삼성 브라우저와 사용자 계정 데이터는 직접 검증하지 못했다.
