# 10초 읽기 제한과 답글 알림 분류

비교 기준: main `a33ad709ee672b728b55ee4dd457235396ec4c78`.

## 변경

- 일반 API 읽기의 제한을 15초에서 10초로 줄였다. 응답 본문 수신도 포함한다.
  쓰기 60초와 파일 업로드 120초는 유지한다.
- 답글 알림은 부모 글 번호 또는 답글 대상 계정 중 하나라도 있으면 답글로 판단한다.
  앱 내 팝업, 알림 목록, 휴대폰 알림에 같은 기준을 적용한다.
- 알림 목록에서도 상대가 자기 글에 이어 쓴 답글이나 다른 대화 속 답글을 답글로 표시한다.
  현재 계정에 보낸 답글일 때만 “내 글에 답글”이라고 표시한다.
- 일반 멘션과 쪽지의 분류는 유지한다. 본문에 @가 있다는 이유만으로 답글로 판단하지 않는다.
- 휴대폰 푸시의 상세 알림 조회는 전체 10초로 제한한다. 네트워크 오류·5xx 등 일시 실패는
  같은 제한 안에서 한 번 더 시도한다. 401·403·404·410·429는 즉시 반복하지 않는다.
- 상세 조회 실패나 계정 정보 부재 때는 기본 푸시의 `mention`을 일반 멘션으로 확정하지 않는다.
  “새 멘션·답글”과 기본 알림 아이콘으로 전달한다. 일반 멘션임을 확인한 경우만 @를 쓴다.
- 토큰 지문 생성이나 계정 메타데이터 읽기가 실패해도 알림 자체는 표시한다.
  계정과 서버를 확인하지 못하면 푸시 토큰으로 다른 서버를 탐색하지 않는다.

Mastodon의 기본 푸시에는 `notification_type: mention`이 들어오지만 답글 부모 정보는 없다.
정확한 세부 분류에는 알림 상세 응답이 필요하다. 이전 코드에서는 이 조회에 실패하면
그대로 @ 배지를 사용했다. 또한 부모 글 번호가 null이고 대상 계정만 남은 모의 응답은
이전 서비스 워커에서 멘션으로, 수정 후에는 답글로 분류되는 것을 재현했다.
실제 사용자가 받은 알림의 당시 응답을 확보하지 못했으므로 어느 경로였는지는 확정하지 않는다.

## 검증

`node --test tests/*.test.cjs`: 63개 통과.

푸시 이벤트를 직접 실행해 답글·일반 멘션·쪽지의 배지, 부모 정보 일부 누락,
일시 실패 후 복구, 시간 초과와 본문 수신 정지, 인증·요청 제한·잘못된 응답,
계정 정보 부재, 열린 앱으로의 신호 전달, 기존 알림 복구를 확인했다.

별도 모바일 Chromium 7개 시나리오에서 팝업과 목록의 분류·문구,
현재 툿으로 이동, 쪽지 우선 표시를 확인했다. 테스트용 제한 시간 변경 없이
실제 API 읽기가 약 10,001ms에 중단되고 안내가 반환되는 것도 확인했다.
삼성 브라우저 실기기의 실제 푸시 수신은 직접 검증하지 못했다.
