# 알림 클릭의 대상 고정과 늦은 이동 방지

비교 기준: main `12182ca5da48acd15bc8fb9f995c4ed6ee078eac`.

## 사용자 기록과 재현

2026-10-19 10:56 KST, 버전 2026-10-18.7의 복사 기록은 GET 11건이고
타래 진입 이벤트가 없다. 이 버전에는 알림 클릭·계정 확인·알림 해석·최종 이동의
연결 기록이 없어서, 해당 휴대폰에서 무엇이 잘못 열렸는지 확정할 수 없다.
정상 HTTP 응답만 있다는 사실로 클릭 경로까지 정상이라고 판단하지 않는다.

이전 코드의 `openNotif`에 두 개의 알림 조회를 시작한 뒤, 나중에 누른 알림 B를
먼저 완료하고 A를 뒤늦게 완료하는 재현을 실행했다. 이동 순서는 B의 툿 다음 A의 툿이었고,
최종 화면이 이전 알림 A에 덮였다. 이전 구현에는 조회 취소·이동 유효성 검사·중복 조회 공유가 없었다.
사용자가 다른 툿으로 이동하거나 계정을 바꾼 경우도 이전 응답이 뒤늦게 화면을 바꿀 수 있었다.

서비스 워커는 `includeUncontrolled:true`로 받은 같은 출처의 모든 창에서
가장 앞에 있는 창을 골랐다. 설치 경로를 제한하지 않아 같은 GitHub Pages 도메인의
다른 앱도 대상이 될 수 있었다. 이 API의 범위는 MDN 문서에서도 확인했다.
이 또한 가능한 오류 경로이며 이번 휴대폰 발생 원인으로 확정한 것은 아니다.

## 수정

- 시스템 알림 조회가 시작되면 이전 툿 화면을 내려놓고 누른 알림을 확인 중이라는 안내를 표시한다.
  이전 타래 요청도 중지한다. 중복된 동일 주소 전달은 하나의 알림 조회를 공유한다.
- 마지막 알림 클릭만 유효하다. 새 클릭, 다른 툿·탭 이동, 뒤로가기, 로그인 화면 이동은
  진행 중인 알림 조회를 취소한다. 취소가 늦게 반영되더라도 결과를 화면에 적용하지 않는다.
- 토큰 지문으로 확인한 수신 계정의 서버와 인증 정보로만 알림을 조회한다.
  조회 응답과 누른 알림의 ID가 일치할 때만 해당 툿으로 이동한다.
  계정 전환은 유효한 결과를 적용하는 시점에 하며, 이미 제거된 계정을 되살리지 않는다.
- 계정 지문이 없거나 일치하지 않으면 현재 계정의 같은 번호를 대신 조회하지 않는다.
  수신 계정 확인 불가, 잘못된 응답, 삭제·정리된 알림은 설명과 알림 목록으로 안내한다.
  조회 실패 때 수신 계정이 확인돼 있으면 그 계정의 목록으로 이동한다.
- 앱 안 팝업도 생성 당시 수신 계정에 묶는다. 팝업 표시 후 계정이 바뀌어도 수신 계정으로
  이동하고 알림의 툿을 연다. 부모 툿 번호로 바꾸지 않는다.
- 알림 ID 문자열은 그대로 유지하고 안전하게 표현할 수 없는 숫자는 다른 번호로 간주하지 않는다.
  잘못된 툿 번호를 받으면 임의의 타래로 이동하지 않는다.
- 서비스 워커의 메시지·업데이트 안내·푸시 전달·클릭 대상은 같은 출처와 설치 경로의 창으로
  제한한다. 다른 앱이 보인다는 이유로 시스템 알림을 생략하지 않는다.
- 앱은 유효한 이동을 처리한 뒤 `ok`를 응답한다. 워커는 실제 `ok`만 성공으로 인정한다.
  연속 클릭 전달과 대체 주소 이동을 순서대로 처리하고 최신 클릭 여부를 검사해,
  이전 클릭의 늦은 주소 이동이 최신 클릭을 덮지 않도록 한다.
