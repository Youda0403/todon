# 프로필에서 한 번 눌러 블언블

비교 기준: main `594a6292b9d3aad115f18f3a6c5757334a026141`.
화면 진단 버전: 2026-10-20.2. 서비스 워커 코드는 변경하지 않는다.

## 사용 방법과 상태

다른 사람의 프로필 `⋯` 메뉴 안에 `블언블` 항목을 표시한다.
프로필 통계 아래에 직접 표시했던 버튼과 설명은 제거했다.
확인창 없이 POST 차단 → POST 차단 해제를 순서대로 실행한다.
반환된 관계에서 양쪽 팔로우와 요청이 없고 차단도 풀렸으면 완료를 알리고 메뉴를 닫는다.
팔로우 버튼과 새 글 알림 버튼도 현재 관계로 다시 그린다.

이미 차단된 계정에서는 기존 메뉴의 `차단 풀기`를 사용한다. 해제만 실행한다.
본인 및 이 서버에서 로그인한 내 다른 계정 프로필에는 추가하지 않는다.
연결이 없는 계정에서는 설명과 함께 비활성화한다.
팔로우·팔로워 중 한쪽만 연결됐거나 요청 중인 관계에도 사용할 수 있다.

기존 프로필 관계 조회 결과를 사용하므로 프로필을 열 때 추가 요청은 없다.
처리 후 팔로우 관련 화면과 사람 선택 목록의 캐시를 무효화한다.

## 순서와 실패 처리

- 계정·서버·상대 ID를 작업 시작 때 고정한다. 도중 다른 계정이나 화면으로 이동해도
  원래 계정으로 차단 해제를 이어 간다. 새 계정의 화면으로 다시 이동시키지 않는다.
- 진행 중 메뉴 항목과 프로필의 팔로우 버튼을 잠그고 `처리 중…`을 표시한다.
  같은 계정·상대의 중복 실행은 한 작업을 공유한다.
- 차단이 권한 오류 등으로 거절되면 중단한다. 네트워크·서버 오류나 잘못된 응답으로
  차단 적용 여부가 불명확하면 이미 차단됐을 가능성을 고려해 해제를 시도한다.
- 해제가 일시적으로 실패하면 해제만 한 번 재시도한다. 각 요청의 대기 한도는 10초다.
- 해제 확인에 실패하면 완료로 표시하지 않는다. 안내를 남기고 버튼을
  `차단 해제 재시도`로 바꿔 같은 메뉴 안에서 다시 누를 수 있게 한다.
  이 항목은 차단을 다시 걸지 않고 해제만 실행한다.
- 상대 ID가 다르거나 관계 정보가 없거나 아직 차단 중인 응답은 해제 성공으로 인정하지 않는다.
  해제 후에도 팔로우 관계가 남아 있으면 이를 안내하고 다시 시도할 수 있게 한다.

두 API를 서버의 한 트랜잭션으로 묶을 수는 없다. 브라우저 프로세스를 종료해 작업이
중단되면 해제가 완료되지 않을 수 있다. 다음에 프로필을 열면 실제 차단 관계를 읽어
`차단 풀기`로 처리할 수 있다. 별도의 인증 토큰이나 대기 작업을 새로 영구 저장하지 않는다.

## 검증

- `node --test tests/*.test.cjs`: 163개 통과. 블언블 검사 13개를 추가했다.
- 앱 스크립트 구문 검사와 `git diff --check` 통과.
- 실제 앱 HTML을 띄운 모바일 Chromium에서 API 응답을 통제해 메뉴 이동 후 9개 시나리오를 확인했다.
  프로필 직접 버튼 부재와 `⋯ → 블언블`, 지속 실패 후 메뉴 안의 해제 재시도,
  자동 재시도, 중복 활성화 방지, 기존 차단 풀기와 프로필 반영,
  권한 거절, 연결 없는 계정, 계정 전환 중 마무리와 320·360·411px 배치를 검사했다.
  테스트 환경에 한글 폰트를 적용해 메뉴 항목의 배치도 확인했다.
- 실제 사용자 계정에 차단·해제 요청을 보내지는 않았다.
