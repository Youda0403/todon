# 링크형 인용과 번호만 있는 인용의 카드 표시

비교 기준: main `c345b09b57c103efe775b6f4e0c94bbf1c7a8ef7`.
화면 진단 버전: 2026-10-20.3. 서비스 워커는 변경하지 않는다.

## 확인한 문제

사용자 스크린샷에서는 본문 아래 마스토돈 툿 주소만 있고 인용 카드가 없다.
기존 렌더러는 `status.quote`가 있는 경우에만 카드를 붙였다.
반면 글쓰기에서는 `quote_approval`이 없는 툿을 인용하면 원글 주소를 붙이는
기존 호환 경로가 있었다. 이 경로로 작성한 글을 읽을 때 주소를 카드로 표시하는 처리는 없었다.

공식 API의 `ShallowQuote`는 승인 상태와 `quoted_status_id`만 주는 경우도 있다.
기존 `quoteEl`은 `quoted_status` 본문이 없으면 승인된 번호를 조회하지 않고
볼 수 없다는 문구로 처리했다. 두 누락을 함께 수정한다.
스크린샷의 실제 인증된 API 응답은 확보하지 못했으므로 해당 서버가 어떤 필드를
반환했는지까지 확인했다고 간주하지 않는다.

## 표시 방식

- 정식 인용의 본문이 포함되어 있으면 즉시 기존 카드로 표시한다.
  승인된 인용의 번호만 있으면 현재 계정으로 원문을 조회해 카드를 완성한다.
- 정식 인용 정보가 없는 글에서는 독립된 줄·문단의 마스토돈 툿 링크 또는
  `quote-inline` 표식을 인식한다. 링크형 인용도 작성자·아이디·시간·본문·미디어를
  담은 카드로 표시한다. 카드가 준비된 뒤에만 중복 주소 줄을 숨긴다.
- 일반 웹 링크, 문장 속 참고 링크, 자기 자신의 주소는 그대로 둔다.
  서로 다른 툿 주소가 여러 개 있고 명시적인 인용 표식도 없으면 대상을 임의로 고르지 않는다.
- 같은 서버 주소는 해당 툿 번호를 조회한다. 다른 서버 주소는 현재 로그인한 서버의
  URL 검색·해석 API를 사용한다. 응답의 원문 주소가 요청한 주소와 일치하는지 검사하고,
  실제 화면 이동은 응답에 담긴 현재 서버의 로컬 툿 번호를 사용한다.
  다른 서버로 현재 계정의 인증 토큰을 보내지 않는다.
- 카드 본문은 인용한 툿을 열고, 작성자 이름·아이디·아바타는 작성자 프로필을 연다.
  부모 툿으로 클릭이 전파되지 않는다. 카드에서 원문을 열 때 이미 받은 본문도 전달한다.
- 툿·타래·알림에서 사용하는 글 카드와 쪽지의 인용 표시에 같은 처리를 사용한다.
  글쓰기의 링크형 인용 안내는 이 앱에서는 카드로, 다른 앱에서는 주소로 보일 수 있다고 설명한다.
  게시물 내용이나 기존 글을 서버에서 수정하지 않는다.

## 로딩과 상태

원래 툿은 인용 조회를 기다리지 않고 표시한다. 화면 근처로 들어온 인용만 불러오며
동시에 두 건까지만 조회한다. 같은 계정의 같은 대상은 요청을 공유한다.
성공 결과는 30초, 실패는 10초 동안 메모리에서 재사용하고 완료 항목은 100개로 제한한다.
수동 재시도는 실패 대기 시간을 건너뛴다. 본문이나 인증 정보를 별도로 영구 저장하지 않는다.

계정과 서버를 요청 때 고정한다. 계정이 바뀌거나 카드가 화면에서 빠진 뒤 도착한 응답은
현재 화면에 적용하지 않는다. 같은 캐시 화면이 다시 붙으면 조회 결과를 받아 카드를 완성한다.
진단에는 인용 방식과 성공·실패, HTTP 상태만 기록하고 주소·번호·계정·본문은 넣지 않는다.

서버가 보낸 인용 승인 대기·거절·철회·삭제·권한 없음 상태는 링크 조회로 우회하지 않는다.
차단·뮤트 상태는 명시적으로 `그래도 보기`를 눌러야 본문을 표시하거나 번호를 조회한다.
내용 경고·민감한 미디어·숨길 단어 설정과 이미 확인된 툿 접근 불가 상태도 반영한다.
조회 실패에는 설명과 재시도를 표시한다. 링크형 인용의 원래 주소는 실패 시 숨기지 않는다.

- `node --test tests/*.test.cjs`: 181개 통과. 인용 주소·조회·계정별 재사용·요청 순서 검사 18개를 추가했다.
- 전체 앱 스크립트 구문 검사와 `git diff --check` 통과.

  링크형 카드와 중복 주소 숨김, 본문·작성자 이동, 정식 본문 포함·번호만 포함된 인용,
  다른 서버의 로컬 번호, 승인 상태, 차단·뮤트의 명시적 보기, 경고·사진,
  삭제·권한 오류, 잘못된 검색 결과, 실패 후 복구, 일반·자기·복수 링크,
  줄바꿈·인용 표식, 화면 밖·접힌 내용의 지연 조회, 숨길 단어,
  계정 전환, 긴 이름의 배치와 화면에서 빠졌다 다시 붙는 경우를 검사했다.
  한글 폰트를 적용해 인용 카드가 보이는 화면도 확인했다.
- 사용자의 서버나 기존 게시물에는 쓰기 요청을 보내지 않았다.
