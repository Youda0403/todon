# 알림 새로고침에서 인용 카드 깜빡임 줄이기

비교 기준: main `2cf379a861b1dfc3715d7dea0896aaf71ccea491`.
화면 진단 버전: 2026-10-20.4. 서비스 워커는 변경하지 않는다.

## 확인한 현상과 원인

첨부된 1.51초 Samsung Browser 화면 녹화를 직접 확인했다. 알림의 ‘전체’ 탭에서
새로고침 완료 무렵 목록이 흐려졌다 돌아오고 인용을 포함한 카드 배치가 다시 잡힌다.

기존 `feedView`는 알림 새로고침 응답을 받을 때 목록의 자식 노드를 모두 지운 뒤
카드를 다시 만들었다. 완성된 링크형·번호형 인용도 로딩 안내부터 다시 만들어졌으며,
성공 결과가 메모리에 있어도 비동기 표시 단계를 다시 거쳤다.
이와 별개로 기존 목록 전체에 220ms의 opacity 0.35 → 1 효과가 적용됐다.
통제된 API를 쓰는 실제 모바일 Chromium에서도 이전 코드의 카드 교체,
펼침 상태 초기화, 목록 전체 페이드 효과를 재현했다.

## 변경

- 알림 번호로 기존 카드를 찾아 내용이 같은 경우 같은 DOM을 유지한다.
  새 알림·삭제된 알림·순서·실제 내용 변경만 반영하며 목록 전체 페이드를 적용하지 않는다.
- JSON 응답의 객체 속성 순서는 내용 차이로 취급하지 않는다.
  좋아요·부스트·답글 수와 버튼 상태만 달라진 경우 기존 상태 객체와 버튼만 갱신한다.
  본문·작성자·필터·인용 대상·인용 승인 상태 변경은 그대로 구분한다.
- 보이는 기존 링크형·번호형 인용은 기존 30초 성공 캐시와 동시 조회 2건 제한을
  사용해 뒤에서 재확인한다. 확인 중에는 카드·내용 경고 펼침·미디어 상태를 유지한다.
  응답 내용이 그대로면 인용 DOM도 교체하지 않는다. 화면 밖이나 접힌 카드는 추가 조회하지 않는다.
- 일시적인 네트워크·서버 오류는 이미 읽고 있던 본문을 유지한다.
  삭제·접근 권한 오류·검증되지 않은 응답에는 기존 인용 본문을 지우고 안내와 재시도를 표시한다.
  정식 인용의 철회·삭제·차단 등 상태는 기존 승인 처리 규칙을 계속 따른다.
- 숨길 단어 경고를 명시적으로 펼친 뒤에도 새 인용 노드에 재확인 함수를 연결한다.
  계정 변경이나 화면 이탈 뒤 도착한 응답을 무시하는 검사는 유지한다.
- 멘션 답장 관리 화면의 최근 3일 조회와 타임라인 갱신 방식은 변경하지 않는다.

## 검증

- `node --test tests/*.test.cjs`: 200개 통과. 알림 카드 유지·순서·내용 변경·실패·페이지 이동
  9개, 인용 재확인·권한·삭제·계정 전환·경고 펼침·진단 정보 10개를 추가했다.
- 전체 앱 스크립트 구문 검사와 `git diff --check` 통과.
- 실제 앱 HTML, 한글 폰트를 적용한 411px·320px 모바일 Chromium, 통제된 API로 11개 항목 확인:
  이전 코드 재현, 같은 알림의 카드·펼침·불투명도 유지, 숫자 갱신과 불필요한 요청 방지,
  캐시 만료 후 느린 응답 중 카드 유지, 인용 원문 수정 반영, 일시 오류 때 내용 유지,
  삭제 안내, 수동 복구, 정식 인용 철회, 새 알림 삽입, 좁은 화면의 가로 넘침 없음.
  브라우저 스크립트 오류는 없었다.
- 사용자 서버에는 쓰기 요청을 보내지 않았다. 실제 Samsung Browser 기기 자체에서
  수정본을 실행한 결과까지 확인한 것은 아니다.
