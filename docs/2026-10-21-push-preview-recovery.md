# 멘션을 새 글로 표시하는 팝업과 미리보기 실패 후 이동 복구

비교 기준: main `0d85e001345bc964f2a5d2032b04f431f2330a1b`.
화면·서비스 워커 버전: 2026-10-21.1. 새 미확인 알림의 이동 프로토콜: 4.
기존에 미리보기 대상이 확인된 경로와 일회성 클릭 확인은 유지한다.

## 이번 기록에서 확인한 범위

2026-10-21 19:44 KST, 화면·워커 버전 2026-10-20.5.
실제 클릭 확인(`notification-launch.verified`)과 수신 계정 확인은 성공했다.
그러나 `notification-target.reason`이 `unverified-display`여서 단건 알림 조회 없이
알림 목록으로 이동했다. 이때 표시하던 문구는 ‘확인된 툿 정보가 없어’라는 표현이었다.
이번 진입에서 HTTP 404·410이나 원글 삭제를 확인한 기록은 없다.
약 22초 뒤의 툿 진입은 별도 동작이며 본문·타래 요청이 모두 성공했다.

기존 워커는 미리보기 상세 조회가 실패하면 `status` 같은 원래 푸시 종류와 제목을
그대로 썼다. 따라서 상세 정보를 확인하지 못한 푸시도 ‘새 글’ 팝업이 될 수 있었다.
또 원래 푸시 종류와 같은 번호의 상세 응답 종류가 다르면 상세 응답을 버렸다.
앱은 미확인 팝업을 클릭해도 다시 조회하지 않고 알림 목록으로만 안내했다.
새 글 구독 알림에 수신 계정의 명시적인 멘션·답글 정보가 있어도 표시 종류는 새 글이었다.

기존 HTML·워커, 통제된 HTTPS API와 실제 모바일 Chromium에서 ‘status 푸시 상세
조회 실패 → 새 글 제목과 목록 전용 대상 → 클릭 후 unverified-display’를 재현했다.
사용자 기기에서 미리보기 조회가 실패한 구체적인 원인은 기존 기록에 없으므로
네트워크·계정 메타데이터·응답 종류 차이 중 어느 것이었는지 확정하지 않는다.

## 표시와 재조회

- 같은 수신 계정의 정확한 알림 번호를 확인한 상세 응답을 표시의 기준으로 삼는다.
  원래 푸시 종류와 달라도 알림 번호가 같으면 확인한 응답으로 제목·아이콘·대상을 함께 만든다.
- 새 글 구독 알림이라도 `in_reply_to_account_id`나 `mentions[].id`가 수신 계정을
  명시하면 멘션·답글로 표시한다. 일반 본문의 `@` 문자열이나 다른 사람의 멘션으로
  추정하지 않는다. 시스템 팝업·앱 안 팝업·알림 목록·앱 안 알림 설정 분류에 같은 기준을 쓴다.
- 미리보기를 확인하지 못하면 제목은 ‘새 알림’, 본문은 앱에서 확인하라는 안내만 표시한다.
  원래 제목·본문·종류로 특정 툿이나 새 글이라고 단정하지 않는다.
- 이 새 미확인 팝업에는 툿 번호 대신 정확한 알림 번호를 확인하는 `notification` 대상을 담는다.
  클릭 시 실제 클릭의 일회성 정보와 수신 계정을 확인한 뒤 그 계정으로 단건 알림을 조회한다.
  경로 안의 두 알림 번호와 응답 번호가 모두 일치해야 하며 실제 응답의 툿·쪽지·프로필로 이동한다.
  번호 불일치·지원하지 않는 종류·안전하지 않은 번호·필수 정보 누락은 목록으로 안내한다.
- 특정 툿을 실제로 보여 준 기존 팝업은 계속 표시 당시 대상과 조회 대상이 같아야 열린다.
  원래 팝업의 본문을 확인할 수 없는 프로토콜 2·3의 목록 전용 알림도 그대로 목록으로 보낸다.
  새 중립 미리보기의 명시적인 프로토콜 4만 알림 번호 재조회를 요청할 수 있다.
- 한 번 사용한 클릭 주소 재실행 방지, 수신 계정 고정, 가장 최근 이동 우선 처리를 유지한다.
  미리보기 상세 조회의 전체 10초 제한·일시 실패 한 번 재시도·동일 계정 확인도 유지한다.
- 상세 정보 부족 안내에서 삭제처럼 들리는 표현을 제거한다. 단건 조회의 404·410 안내와
  단순 정보 누락·일시 실패 안내를 구분한다. 기존에 별도로 확인한 접근 불가·필터 처리는 유지한다.

## 백그라운드 진단

화면이 닫혀 있을 때의 미리보기 결과도 최근 20개까지 워커 메타데이터 캐시에 남긴다.
종류 힌트·확인한 종류·표시 종류, 성공·HTTP 오류·시간 초과·잘못된 응답·네트워크 오류·
계정 정보 확인 실패, HTTP 상태·시도 횟수·유형 차이 여부만 기록한다.
주소·알림 번호·툿 번호·계정 번호·토큰·수신 지문·제목·본문은 추가하지 않는다.
다음 워커 버전 확인 때 앱 범위의 창에만 전달하며, 앱은 허용한 필드만 가져오고
중복·너무 오래된 항목을 제거해 ‘문제 확인용 기록 복사’에 포함한다.
