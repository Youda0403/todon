# 여러 계정의 알림 누락·읽음 위치·쪽지 이동 수정

기준 main: `f30744998acd642f42128d2f5d55190c71371fa5` (2026-10-21.1).
화면 기록·서비스 워커 버전: **2026-10-23.1**. 알림 클릭 경로 프로토콜은 기존 4를 유지한다.

## 수정한 동작

### 계정 전환 도중 도착한 이전 응답

계정을 저장·선택할 때 현재 계정과 토큰에 연결된 알림 조회 실행을 확인한다. 계정이나 토큰이 바뀌면 이전 실행의 AbortController를 중단하고 조회 기준·미확인 목록·팝업 중복 판정 상태를 새 실행으로 교체한다. A → B → A로 돌아와 같은 계정 객체를 다시 선택해도 이전 A 실행은 적용되지 않는다.

알림 목록과 읽음 위치 요청에 계정·중단 신호를 명시한다. 두 요청의 각 응답 뒤에 현재 실행인지 확인하고, 읽음 위치 저장 키와 서버 쓰기도 수신 계정을 명시한다. 같은 계정의 동시 조회는 한 작업을 공유한다. 이전 응답이 새 실행의 조회 기준·읽음 위치·배지·팝업에 영향을 줄 수 없게 했다.

### 다른 계정 화면이 열려 있을 때의 푸시

워커는 보이는 창에 알림 번호·수신 토큰의 지문·처리 기한을 보내고 MessageChannel로 처리 결과를 확인한다. 앱은 현재 계정과 지문이 맞는 경우에만 그 계정의 정확한 알림 한 건을 조회한다. 번호 일치, 현재 계정·실행·화면 가시성·기한을 다시 확인한 다음 앱 팝업 또는 현재 대화 갱신을 처리하고 확인 응답을 보낸다.

앱이 처리했다고 확인한 경우에만 시스템 팝업을 생략한다. 다른 계정 화면, 이전 화면 버전의 미응답, 창 정지, 조회 실패·시간 초과, 번호 불일치는 워커의 기존 시스템 팝업 경로로 이어진다. 수신 계정이 맞는 보이는 창을 우선순위대로 확인하며 한 창이 처리하면 멈춘다.

화면의 처리 기한은 2초이며 워커는 확인 응답 전송에 100ms 여유를 둔다. 기한을 지난 화면 응답은 팝업을 뒤늦게 만들 수 없다. 같은 알림의 동시 상세 조회를 공유하고, 처리한 알림은 현재 실행에서 최대 200개까지 중복을 막는다. 초기 목록에 이미 포함되어 있던 새 푸시도 앱 팝업에서 빠지지 않도록 했다. 숨긴 툿이나 사용자가 꺼 둔 알림 종류는 의도적으로 억제하며 시스템 팝업으로 중복 표시하지 않는다.

창 메시지에는 인증 토큰·본문을 보내지 않는다. 추가 진단은 처리 여부만 기록한다. 미리보기 실패 시 중립 표시, 정확한 알림 재조회, 수신 계정 고정 및 일회성 클릭 확인은 유지한다.

### 다른 계정으로 받은 쪽지

대화 참여자 계산 함수에도 수신 계정을 전달한다. 알림 클릭 후 계정이 전환되기 전에 대화방 주소를 계산해도, 수신 계정 자신을 참여자 목록에서 정확히 제외한다. 시스템 팝업, 중립 미리보기 재조회, 앱 팝업에 같은 계산을 사용한다. 그룹 쪽지·부스트 래퍼·자기 자신과의 쪽지도 검사했다.

## 검증

`node --test tests/*.test.cjs`: **256개 통과**. 기존 235개에 21개 검사를 추가했다. 앱 전체 인라인 스크립트 파싱, `node --check sw.js`, `git diff --check`도 통과했다.

추가 검사는 늦은 목록·읽음 위치 응답, A → B → A 전환, 취소 이후 오류, 동일 번호를 가진 다른 계정, 요청 공유와 재시도, 토큰 변경·로그아웃, 전경 수신 계정 확인, 초기 목록·중복 푸시, 화면 숨김·기한 초과·번호 불일치, 의도적인 억제, 워커 확인 응답·이전 화면 호환, 실제 쪽지 참여자 함수를 사용하는 클릭·복구 경로를 포함한다.

HTTPS 앱과 별도 HTTPS 모의 마스토돈 API, 실제 Chromium 서비스 워커, 411×922 모바일 화면에서 이전 버전과 수정 버전을 비교했다. 두 계정에는 서로 다른 서버 주소를 사용했다.

| 재현 조건 | 이전 버전 | 수정 버전 |
| --- | --- | --- |
| A 화면에서 B 쪽지 푸시 | 앱·시스템 팝업 모두 0개 | B의 시스템 팝업 1개, A 계정 선택 유지 |
| A 화면에서 B 쪽지 팝업 클릭 | 자기 자신이 포함된 주소, 빈 대화 | 상대만 포함된 주소, 기존 쪽지 표시 |
| B 전환 후 늦은 A 읽음 위치 응답 | B의 조회 기준 100이 900으로 덮임 | B의 조회 기준·읽음 위치 모두 100 유지 |

수정 화면의 추가 동작 및 이전 화면 호환 14개 항목이 통과했고, 이전 소스의 결함 재현 3개를 함께 확인했다. 현재 계정의 앱 팝업, 중복 조회 방지, 느린 전경 조회의 시스템 팝업 전환과 늦은 중복 방지, 닫힌 앱의 재조회, 사용한 주소 재실행 차단, 인용 DOM 보존, 직접 답글 수, 문맥 접기·펼치기, 삭제된 툿 안내, 진단 정보 정리를 확인했다. 브라우저 스크립트 오류는 0개였다.

시스템 팝업은 표시 인자를 수집했고 푸시·클릭은 테스트 이벤트로 실제 핸들러를 호출했다. HTTP·MessageChannel·캐시·주소 이동·화면 렌더링은 실제로 실행했다. 실제 휴대폰 OS 알림창이나 당시의 서버 응답을 직접 재현한 검사는 아니다. 사용자의 마스토돈 서버에는 요청하지 않았다.

앱의 `index.html`, `sw.js`, 관련 검사와 이 기록만 변경한다. 같은 저장소의 `operator/` 앱 및 다른 파일은 배포 트리에 그대로 보존한다.
