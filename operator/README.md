# 커뮤 운영실 · Curtain Call

`todon`의 planet.moe 로그인·계정 전환 흐름을 참고해 별도 앱으로 만든 커뮤니티 운영용 첫 버전입니다. 기존 러너용 앱의 `index.html`, `sw.js`, 계정 저장소는 변경하지 않습니다.

**배포 소스 위치:** `Youda0403/todon` → `main` 브랜치 → `operator/` (최초 개발 브랜치: `community-ops`)

**배포 대상:** 본인의 Cloudflare Workers Free + D1 Free. ChatGPT Sites에 배포하는 앱이 아닙니다. 유료 API와 생성형 AI를 사용하지 않습니다.

## 지금 준비할 것

1. [Cloudflare](https://dash.cloudflare.com/)에 가입하고 이메일을 인증합니다. 도메인 추가·구매나 Workers Paid 가입은 필요하지 않습니다.
2. **Storage & databases → D1 SQL Database → Create Database**에서 `todon-ops-db`를 만듭니다. 위치 힌트를 고를 수 있으면 아시아 쪽을 선택해도 됩니다.
3. 생성한 데이터베이스의 **Database ID**를 복사합니다. 이 값은 저장소를 식별하는 값으로, 비밀번호나 API 토큰이 아닙니다.
4. `wrangler.jsonc`의 `REPLACE_WITH_YOUR_D1_DATABASE_ID`를 그 ID로 바꿉니다. 대화에서 이 ID를 알려주면 코드에 반영할 수 있습니다. Account API Token, Global API Key, 마스토돈 토큰, 비밀번호는 대화에 보내지 마세요.

## 데이터베이스 초기화

D1의 `todon-ops-db` → **Console**에 `schema.sql` 전체 내용을 붙여 넣고 **Execute**합니다. 기존 테이블을 삭제하지 않는 `CREATE TABLE IF NOT EXISTS` 방식입니다. 같은 스키마를 다시 실행해도 이미 저장된 러너 기록을 초기화하지 않습니다.

## Cloudflare에서 앱 연결하기

Workers & Pages에서 새 Worker를 만들고 GitHub 레포를 연결합니다. 생성 화면의 용어와 메뉴 위치는 달라질 수 있으므로 다음 값이 맞는지 확인합니다.

| 설정 | 값 |
|---|---|
| Git repository | `Youda0403/todon` |
| Git branch / Production branch | `main` |
| Worker name | `todon-ops` |
| Root directory | `operator` |
| Build command | 비워 둠 |
| Deploy command | `npx wrangler deploy` |

`main` 브랜치의 레포 루트에는 기존 러너용 앱이 있고, `operator` 폴더에 운영실이 있습니다. 운영실 배포는 반드시 Root directory / 경로에 `operator`를 지정하세요. `database_id`에는 전달받은 D1 ID가 반영되어 있습니다. 다른 저장소를 사용하려면 해당 값도 변경하세요.

배포 후 Worker → **Settings → Variables and Secrets**에 다음 값을 추가합니다.

| 이름 | 종류 | 내용 |
|---|---|---|
| `ADMIN_KEY` | **Secret** | 비밀번호 생성기 등으로 만든 24자 이상의 임의 운영 암호 |

이 값은 빌드 전용 환경변수가 아닌 **실행 Worker의 Secret**으로 등록합니다. GitHub 소스나 공개 설정에 적지 않습니다. 앱에 연결할 때 같은 운영 암호를 입력하므로 본인이 별도로 보관해야 합니다. 저장된 마스토돈 토큰 암호화에도 이 값을 사용하므로, 나중에 바꾸면 마스토돈 계정들을 다시 연결해야 합니다.

**Bindings**에 D1 바인딩 `DB`가 `todon-ops-db`로 연결되었는지 확인합니다. **Triggers / Cron**에는 `* * * * *`가 있어야 합니다. 설정 파일에 이미 포함되어 있으며, Cron 추가·수정은 전파에 최대 15분이 걸릴 수 있습니다.

## 첫 사용

1. 생성된 `https://todon-ops.…workers.dev` 주소를 엽니다.
2. **서버 연결**에서 운영 암호를 입력합니다. 암호는 이 탭의 sessionStorage에만 보관하고, 마스토돈 토큰은 브라우저로 내려주지 않습니다.
3. **운영 계정 → planet.moe 계정 연결**에서 실제 마스토돈 화면으로 이동해 로그인·권한을 승인합니다. 여러 계정을 반복해서 연결할 수 있습니다.
4. **아이템·능력치**에서 기본 능력치와 아이템 목록, 사용 효과를 지정합니다.
5. **러너 기록부 → 러너 등록**에 아이디를 한 줄에 하나씩 입력합니다. 한 번에 최대 30명입니다.
6. **자동봇 제작소**에서 템플릿을 고르고 발신 계정을 지정합니다. 블록과 키워드를 고친 뒤 연습창에서 시험하고, **이 규칙 켜기 → 규칙 저장**합니다.
7. 실제 테스트용 러너로 확인할 준비가 되면 **자동봇 켜기**를 누릅니다. 공지와 스토리 예약은 각 예약별로 실행되며 이 스위치와 분리되어 있습니다.

## 기능

- 여러 운영 계정 연결, 발신 기본 계정 전환, 계정별 별명·자동 확인 제어.
- 한글 블록 편집과 위아래 이동. 키워드 포함/완전 일치, 일일 횟수, 재사용 대기시간.
- 대사 출력, 가중치 랜덤 선택, 주사위, 사칙연산, 능력치 변경, 물건 지급·사용, 조건 검사, 상태·가방·최근 기록 조회.
- 연습창은 실제 실행과 같은 블록 엔진을 사용합니다. 실계정으로 보내지 않으며 횟수·대기시간은 시험하지 않습니다.
- `확인` 템플릿: 러너가 연결한 봇에 `@봇계정 확인`을 보내면 상태와 소지품을 답글로 출력합니다. 원하면 키워드를 `@확인` 또는 `[가방]`으로 바꿀 수 있습니다.
- 등록한 러너만 처리합니다. 여러 규칙이 동시에 맞으면 발신 계정의 위쪽 규칙 하나를 실행합니다.
- 러너별 현재 능력치·물건과 변경 이력. 물건을 사용해도 이전 획득 이력은 남습니다.
- 스토리 대본은 한 묶음당 최대 30장면. 발신 계정·공개 범위·시작 시각·최소 60초 간격, 미리보기, 일시정지·재개·남은 장면 취소.
- 월간 캘린더, 오늘 일정, 운영 메모. 이 버전은 앱에서 보여주는 일정 알림이며 브라우저 푸시는 아직 없습니다.
- 서버의 초대 관리에서 미리 만든 링크 저장·원클릭 복사. 서버 초대 권한이 필요하며 새 초대장을 API로 생성하지 않습니다.

## 선택지형 조사와 아이템 설정

1. **아이템·능력치**에 `HP` 같은 숫자 변수와 획득·사용 아이템을 등록하고 저장합니다. 사용 가능한 아이템은 키워드, 소모 여부, 효과와 사용 후 답장을 정할 수 있습니다.
2. **자동봇 제작소 → 선택지형 조사**에서 장면을 고릅니다. 화면의 ①은 장면 도착 시 이야기, ②는 그 장면의 결과 처리, ③은 다음 선택지 또는 종료 문장입니다. ① 장면 이야기는 선택 사항으로, 비우면 앞 문장 없이 결과와 다음 선택지 또는 종료 문장만 보냅니다. 마지막 장면에서 결과만 보내려면 ①과 ③ 종료 문장을 모두 비웁니다.
3. **확률별 결과 나누기**는 예를 들어 약초 25%, 돌 25%, 실패 50%로 설정합니다. 각 결과 안에는 여러 아이템 지급, HP 감소, 랜덤 능력치 변화, 계산을 함께 추가할 수 있습니다. 확률 합계는 100%여야 합니다.
4. **변수 넣기**로 등록한 수치를 문장에 넣습니다. `{HP}`는 현재 HP, `{물건:열쇠}`는 열쇠 소지 수량입니다. 결과 답장과 종료 문장은 결과를 적용한 뒤의 수치를 사용합니다.
5. 선택지의 **보여줄 조건**에 아이템 수량이나 능력치 조건을 정하면 조건이 맞는 선택지만 표시합니다. 숨긴 키워드를 직접 보내도 이동하지 않습니다. 표시 번호는 보이는 선택지에 맞춰 다시 매깁니다.
6. **대화하며 연습하기**의 시험용 소지품·능력치를 바꿔 조건과 아이템 사용을 확인합니다. 조사 중단 명령은 없으며, 다음 답장을 보내면 저장된 장면부터 이어갑니다. 같은 조사에서 같은 장면의 결과는 한 번만 적용합니다.

삭제 버튼은 확인 창을 거칩니다. 등록 목록에서 항목을 삭제해도 기존 러너의 수량과 수치는 보관됩니다. 사용 아이템 등록을 삭제하면 해당 사용 키워드는 꺼집니다.

## 상시 아이템·최대치·선택지 인식어

- **아이템·능력치 → 아이템 선택 → 소지하는 동안 상시 발동**을 켜면, 가방에 있는 동안 능력치나 최대치를 보정합니다. 예를 들어 힘 +2 부적은 기본 힘 5를 적용 수치 7로 보여 주며, 부적이 없어지면 다시 5가 됩니다. 확인할 때마다 기본 수치에 더하지 않습니다. 같은 물건은 한 번만 적용하거나 가진 개수만큼 중첩하도록 고를 수 있습니다. 사용 효과와 상시 효과를 함께 설정할 수도 있습니다.
- 능력치 행의 **최대치**를 비우면 상한이 없고, 숫자를 넣으면 회복·랜덤 상승·계산·상시 보정까지 적용한 최종 수치가 그 상한에서 멈춥니다. 최대치 보정 아이템은 상한이 등록된 능력치에 적용됩니다. 러너 기록 수정은 기본 수치를 편집하며, 적용 중인 수치는 별도로 표시합니다.
- 조사 선택지의 **러너에게 보여줄 선택지**에 `칼로 벗긴다`, **인식할 키워드**에 `칼, 벗기기`를 적으면 두 단어 중 하나로 선택할 수 있습니다. 문구 전체와 표시 번호도 인식합니다. 인식어를 비우면 기존처럼 선택지 문구로 인식하고, 여러 선택지가 동시에 맞으면 다시 선택하도록 안내합니다. 보여줄 조건이 맞지 않는 선택지는 인식어로도 고를 수 없습니다.
- **대화하며 연습하기 → 시험용 능력치·소지품 바꾸기**에서 기본 수치와 소지 수량을 바꾸면, 상시 보정과 최대치를 반영한 현재 수치를 바로 확인할 수 있습니다.

## 조합 레시피와 아이템 설명

**아이템·능력치 → 조합 레시피 → + 레시피 등록**에서 재료·필요 능력치·성공 확률·결과 효과를 함께 관리합니다. 아이템 설정의 **이 아이템이 들어가는 레시피**에서도 해당 아이템을 재료로 미리 넣어 등록할 수 있습니다.

예를 들어 돌 1개(소모 끔) + 마른 풀 1개(소모 켬), 힘 3 이상, 성공 확률 100%로 설정합니다. 성공 문장에 `불을 피웠습니다.`를 적으면 물건을 만들지 않고 이야기만 진행할 수 있고, 성공 효과에 아이템 획득을 추가하면 불씨 같은 완성품도 함께 줍니다. 능력치 조건은 상시 보정을 반영한 수치로 확인하며 능력치를 소모하지 않습니다. 재료나 능력치가 부족하면 실패 시 재료 소모 설정과 관계없이 아무것도 차감하지 않습니다.

**러너가 키워드로 직접 조합할 수 있음**을 켜면 등록한 키워드(예: `[불 피우기]`)를 봇 계정에 멘션해 실행합니다. 꺼도 조사 결과나 아이템 사용 효과에서 **등록한 레시피 실행**으로 불러올 수 있습니다. 아이템 단독 사용과 조합은 각각의 키워드를 사용합니다. 사용 효과에 레시피 실행이 포함되어 있으면 레시피에서 재료 소모를 관리하고, 아이템 사용 자체로 한 개를 더 차감하지 않습니다. 레시피 결과에는 다른 레시피 실행이나 아이템 사용을 다시 넣을 수 없으며, 획득·능력치 변화·문장 등을 직접 설정합니다.

여러 재료 이름이 모두 들어간 문장에 반응시키려면 레시피의 **인식 방식 → 여러 키워드가 모두 들어가면**을 고르고 **모두 들어가야 할 키워드**에 `돌, 마른 풀`을 적습니다. **띄어쓰기 무시**를 켜면 `돌과 마른풀을 조합한다`, `마른 풀 + 돌` 모두 인식하고, 한 키워드만 있으면 반응하지 않습니다. **재료 이름으로 채우기**는 현재 재료 이름을 인식어로 넣어 줍니다. 인식어는 재료 목록과 별도로 편집할 수 있습니다. **인식을 시험할 문장**에서는 저장 전에도 인식 여부를 확인하며 실제 조합을 실행하지 않습니다. 실제 실행 시에는 소지 재료와 능력치 조건도 계속 확인합니다. 기존 레시피는 인식 방식을 바꾸기 전까지 원래 키워드 방식을 유지합니다.

등록한 아이템의 설명은 자동 획득 시 함께 출력하고 가방 조회에는 짧은 설명을 표시합니다. 러너는 `[설명 돌]`처럼 멘션해 현재 가진 아이템의 전체 설명을 볼 수 있습니다. 이 설명 명령은 조사 중에도 장면을 진행시키지 않습니다. 운영실에서는 **러너 기록부 → 러너 선택 → 가방에서 아이템 살펴보기**에서 항목을 펼쳐 확인합니다. 운영자가 직접 소지품을 수정하는 작업은 별도의 획득 툿을 보내지 않습니다.

레시피의 **이 레시피 시험하기**는 실제 계정과 기록을 바꾸지 않습니다. 재료·조건·결과는 한 작업으로 처리하고, 같은 멘션의 중복 처리를 막습니다. 사용 중인 레시피를 삭제하려면 해당 레시피를 실행하는 작업부터 제거해야 합니다. 재료·조건·레시피 삭제에는 확인 창이 표시됩니다.

## 무료 환경의 처리 방식과 한계

실행 트리거는 1분 간격이지만 실시간 스트리밍은 아닙니다. 매번 모든 봇 계정을 동시에 확인하지 않고 계정을 번갈아 확인합니다. 계정 수·페이지 수·대기열에 따라 답글은 여러 분 늦어질 수 있습니다. ‘26명 동시에 호출’은 정상적인 대기열 처리를 확인할 시험 사례이지, 1분 이내 응답 보장이 아닙니다.

D1 Free의 호출당 50쿼리를 넘지 않도록 예약 실행에서 쿼리 수를 세고 남은 명령을 다음 실행에 넘깁니다. 이것만으로 Workers의 호출당 10ms CPU 제한 통과를 보장하지는 않습니다. 실제 Cloudflare에서 CPU 시간·오류와 planet.moe 응답을 확인한 뒤 개장하세요. 운영 앱의 ‘오늘 처리한 명령’은 Cloudflare 과금 단위나 실제 D1 행 사용량과 다릅니다. 실제 한도는 Cloudflare 대시보드에서 확인합니다.

한국 시간 하루 전체 명령 상한 기본값은 1500회입니다. 상한에 도달한 미처리 명령은 다음 날로 넘어갈 수 있습니다. 조회 규칙에도 재사용 대기시간을 두고, 조사·보상 규칙에는 일일 횟수를 지정하는 것을 권합니다. 무료 한도를 계속 초과하면 자동 유료 전환 대신 작업 오류가 발생할 수 있으므로 사용량에 맞춰 상한을 조절합니다.

능력치·아이템·사용 횟수·출력 대기열은 한 DB 배치로 저장합니다. 같은 알림 ID는 다시 처리하지 않습니다. 답글은 원문의 공개 범위를 넓히지 않도록 멘션 전용 또는 팔로워 전용으로 전송합니다. 봇이 상대를 팔로우하지 않은 경우 팔로워 전용 답글이 의도대로 보이는지 실제 계정에서 먼저 확인하세요.

네트워크 오류 때는 같은 Idempotency-Key로 재시도합니다. Mastodon의 중복 방지 키는 무기한이 아니므로 최초 전송 후 55분이 지나거나 반복 오류가 발생한 출력은 ‘확인 필요’로 멈춥니다. 이때 수동으로 무턱대고 재전송하지 말고 실제 계정에 이미 올라갔는지 확인합니다. 앞 스토리 장면이 전송되지 않으면 뒤 장면도 기다립니다. 이미 전송 요청이 시작된 작업은 일시정지·취소 버튼으로 되돌릴 수 없습니다.

## 기록 보관

**연결·설정 → 기록 파일 내려받기**는 설정·러너 상태와 최근 변경 이력 100개, 출력 요약 100개 등을 내보내는 보조 파일입니다. 비밀키를 포함하지 않으며 전체 재해 복구 백업은 아닙니다. 전체 백업은 D1의 Export를 사용하세요. D1 Free의 시점 복원 보관은 현재 7일이므로, 10일 커뮤라면 중간 및 종료 때 별도 내보내기를 해두세요.

## 개발 검증

Node.js 22.13 이상(내장 `node:sqlite` 사용)에서 `npm test`로 실행합니다. 별도 패키지 설치 없이 블록 엔진, 인증, 동시 설정 수정 방지, 중복 알림, 상태 저장 원자성, 26명 명령의 페이지·대기열 처리, 실패한 장면 뒤의 출력 중단을 검증합니다.

이 시험은 SQLite와 모의 Mastodon 응답을 사용합니다. 실제 planet.moe OAuth 승인·게시, Cloudflare Workers CPU와 D1의 네트워크 동작은 배포 후 확인해야 합니다.

### 편집 화면과 지문 키워드

- 아이템 / 능력치 / 레시피 탭으로 편집 대상을 나눕니다.
- `이 아이템 설명만 저장`은 저장된 설정에서 해당 설명만 변경합니다. 신규 아이템은 사용·상시 효과를 끈 설명 항목으로 먼저 저장합니다. 미완성 효과, 다른 목록의 편집은 보내지 않고 화면의 초안에 남깁니다. 전체 설정 저장은 기존 검증을 유지합니다.
- 아이템 사용 키워드는 쉼표로 구분합니다. 한 키워드가 지문에 포함되면 반응하며 띄어쓰기는 무시합니다. 동의어를 자동 추론하지 않으므로 필요한 표현을 추가합니다. 서로 다른 아이템의 동일 키워드는 저장을 거절합니다.
- 일반 자동봇·조사 시작 키워드도 포함 인식에서 쉼표로 여러 표현을 지정할 수 있습니다. 기존의 정확히 일치 모드는 그대로 유지하며, 띄어쓰기 무시를 별도로 선택할 수 있습니다.
- 조사 전체 흐름도에는 이야기·선택지·조건·연결 장면·기록 변화·종료 문장이 표시됩니다. 반복 연결은 참조로 표시하여 무한 전개를 막습니다. 장면 버튼은 편집 화면으로 이동합니다.
- 실행 순서 요약은 위에서 아래 순서를 보여주고 확률 결과와 랜덤 답장 후보를 가지로 표시합니다. 키워드가 겹치는 다른 규칙까지 동시에 실행한다는 뜻이 아닙니다.
